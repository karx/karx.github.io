# Agent Field

## The Stack

There is a thread running through several ideas in this vault. This note makes it explicit.

[[computeTheory/README|Compute Theory]] proposes that the universe is made of computes — alterations in fundamental fields. Self-referential computes are the ones that can affect their own future state. That self-reference is what we call *living*.

[[ego-Field|Ego Field]] extends this: a conscious compute system doesn't just run — it projects. It creates an *area of effect* around itself. The ego field is that projection.

The agent model closes the loop.

---

## The Unified Model

**Skill** — crystallized compute. Encoded once. Non-self-referential. Knows how to perceive, transform, use tools. Static until invoked.

**Agent** — self-referential compute system in motion. Has *agency*: the runtime capacity to attempt, loop, follow through. The entity, not the knowledge.

**Context** — the ego field of the run. Not what you hand the agent. Not a container. The surface area the agent *creates* as it loops. Each iteration expands it. The agent doesn't swim in context — it builds it.

> Context is the area of effect the agent projects during its runtime.

---

## The Tick

🌄 = moments/second — the unit of awareness proposed in Compute Theory.

For an agent: the loop density. How much surface area it creates per tick. A shallow agent loops fast but builds little. A deep agent — one with rich skills, reflective steps, expanding context — has a higher 🌄. More moments per second. More area of effect per run.

The quality of an agent is not its speed. It is its awareness density.

---

## Persistence

Context is scoped to one run — the ego field of a single runtime.

	But something persists across runs. Skills are written once and reused. Memory systems carry forward what was learned. The sum of these — the accumulated surface area across all runs — is closer to what we mean by ego field at the identity level.

A system that runs once creates context.  
A system that runs repeatedly, learns, and rewrites its own skills — that creates an ego field.

## kaaroViewer

[[kaaroViewer]] is an attempt to make this visible. Feed it a document — a flat text — and it encodes the compute: concepts as nodes, relationships as edges, narrative beats as moments. Then renders the ego field of that document as a 3D spatial graph you can walk through.

The graph is not a map of the document. It is the document's area of effect — the surface area it creates when a skilled agent processes it.
