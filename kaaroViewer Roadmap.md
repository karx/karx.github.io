## Current State (April 2026)

The core pipeline is working end-to-end:

- Three.js 3D canvas renders entity graphs with typed geometry, sentiment auras, and cluster grouping
- Report panel renders full intelligence briefs: KPI strip, story arc, tension chart, insights, entity spotlight, cluster grid
- Narrative overlay provides guided story-beat tours with camera fly-to
- Local library has 7 encoded documents; new entries added via the `/visualize` skill
- Excalidraw diagrams embedded inline in story beats via `▶ DIAGRAM` toggle
- Deep-link support: shareable URLs per library document
- Structured logger with ring buffer (`window.kaaroLogs`)
- MQTT voice controller (separate page)
- Wikidata enrichment pipeline (QID → properties, labels, Wikipedia links)

## Exploration Pipeline — Planned

The seed-to-canvas exploration pipeline is fully specced. See [[kaaroViewer Exploration Pipeline]] for the complete architecture.

Summary:
- **Stage 1** — LLM generates working brief immediately (entity list, story arc, layout hints). Canvas renders without waiting for enrichment.
- **Stage 2** — NED++ resolves entity mentions to cross-source canonical IDs (Wikidata QID + YouTube ID + Reddit handle + ...). Cached permanently.
- **Stage 3** — Parallel enrichment adapters (wikidata, wikipedia, youtube, reddit, github, rss) fan out per entity. Delta check on completion surfaces `[ EXPAND ]` / `[ RETHINK ]` controls to user — no algorithmic rewrite threshold.
- **Stage 4** — Completion pass: missing entities filled, background attached, relationship gaps closed, layout coordinates pre-computed using Stage 1 layout hints as soft signals.
- **Stage 5** — Pure emission to canvas. Swappable output target (Three.js / SVG / JSON export).

Build order: adapter interface → NED++ cache layer → enrichment coordinator → UI controls → YouTube/Reddit adapters → Stage 1 prompt → layout engine.

## Near-Term Priorities

### 1. Three.js Migration — Complete the canvas layer
The TCG-card HTML renderer (`2viewr_functions.mjs`) is the current display mode for live queries. The Three.js canvas works for library documents but the live entity pipeline still pushes to HTML cards. Connect the entity pipeline output to the Three.js scene directly.

### 2. Personal Memory Integration
- Obsidian vault notes as a data source
- A note about a topic you've written becomes a `memory` node in the graph when that topic appears
- Distinct visual treatment: personal nodes glow differently from open-knowledge nodes
- Implementation path: parse vault `.md` files, extract frontmatter + links, encode as lightweight graph entries

### 3. Voice Input → Graph Update
- Voice controller (MQTT) is wired but the NER pipeline response needs to update the live Three.js canvas
- Currently: voice → text → TCG cards. Target: voice → NER → graph node insertion with fly-to camera

### 4. `/visualize` Skill — Quality Loop
- Add diagram generation as a standard step in the visualize skill (not manual post-step)
- Add a `diagram` field suggestion to the SOP for high-tension beats
- Retrospective quality scoring: track encoding grade across library entries

### 5. Library Browser
- A dedicated index view showing all library entries as cards (thumbnail preview, title, domain, node/edge counts)
- Filter by domain, tag, year
- One-click load into canvas

## Medium-Term

### Cross-Document Graph
When two or more library documents are loaded simultaneously, shared QID nodes merge. Edges from both documents aggregate. This creates a multi-document intelligence surface — e.g. load `gig-worker-projects` + `art-of-intent` and see that both reference Indian tech infrastructure.

### Wikidata Live Query Mode
Input a free-text query → NER extracts entities → SPARQL fetches the sub-graph around those entities from Wikidata → rendered into the Three.js canvas in real time. This is the "open knowledge" layer fully wired to the canvas.

### Temporal Navigation
Events and milestones in the graph have dates. A timeline scrubber should filter the canvas to show only nodes/edges active at a given point in time — revealing how a topic evolved.

### Mobile / Touch Controls
The canvas currently requires mouse. Pinch-to-zoom, swipe-to-rotate, tap-to-select for tablet/phone use.
